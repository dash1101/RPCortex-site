An operating system for microcontrollers.

RPCortex gives a Raspberry Pi Pico a shell, a filesystem, accounts, Wi-Fi, a package manager and over-the-air updates. On the RP2350 boards a package runs in a sandbox, so a bad one costs a command and not the board.

Get RPCortex Read the docs

What is new in v2

190×vs v1, same workload

RPCMark scores 1.05 million at 230 MHz, against v1's 5,000 to 6,000 at the same clock. At the 150 MHz it starts at, about 700,000.

2 coresboth in use

Tasks run on either core. ps shows every one with its stack and CPU time, and kill stops one.

5 regionspackage sandbox

On RP2350 a package runs unprivileged. A bad pointer costs that command, not the board.

OTAand a way back

Update over Wi-Fi, checked against a checksum. The old firmware is kept, and update rollback puts it back.

What is in it

What it includes

Shell

Coloured prompt, history that survives a reboot, Tab completion. Pipe with |, chain with && and ||, redirect with >.

Both cores

v1 could not touch core 1 at all. Here an unpinned task lives on core 1 about 99% of the time.

Scripting and automation

Run commands at boot (startup) or on a timer (task), and write .rps scripts with variables, if and while.

Filesystem

littlefs in the format a v1 device already uses. ls, cd, cp, tree, df, and a USB drive to drag files on and off.

Accounts

Salted SHA-256 passwords, roles, per-user home directories, and a guided first run.

Wi-Fi and the network

Scan, connect, saved networks with sealed passwords, autoconnect. wget, curl, ping, nslookup, HTTPS.

Packages

Install by name from a repository, upgrade, remove. Compiled .app files that load at runtime, sandboxed on the RP2350.

Recovery

A black box that survives a reset. safeboot loads nothing. Three failed starts load nothing, then restore the saved firmware, and only then rebuild the filesystem. (v2.00-beta has a bug that stops this triggering; the next release fixes it.)

Boards

Supported boards

Every result on this page came from a Pico 2 W. The other three build and pass the image checks and have not been booted yet. They have no package sandbox on RP2040: the protection regions cost more RAM than those boards have. v1 remains the answer on an ESP32-S3 until the port lands.
