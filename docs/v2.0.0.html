Getting Started

What you need:

  • A Raspberry Pi Pico, Pico W, Pico 2, or Pico 2 W
  • A serial terminal at 115200 baud — PuTTY on Windows, minicom or screen on Linux/macOS

That is the whole list. v2 is a firmware image, not a set of files copied on top of something else, so there is nothing to install underneath it.

Installation

  1. Hold BOOTSEL and plug the board into USB. It appears as a drive called RP2350 or RPI-RP2.
  2. Drag the .uf2 for your board onto it. Pick it from the Get page.
  3. The board reboots by itself. Open your serial terminal at 115200 baud.
After the first install you should not need that page again. The device updates itself — see OS Updates.

First boot

A short setup runs the first time:

  1. You set the root password
  2. A guest account is created, which accepts any password
  3. You are offered a WiFi connection, on boards that have a radio

After that you are at the shell prompt. The setup only runs once.

Boot Sequence

Boot brings up the filesystem, the registry, the log ring and the scheduler, prints the banner, then starts the shell as its own task. If WiFi autoconnect is enabled, the join runs in the background — the login prompt appears immediately rather than waiting for the network.

If the previous boot crashed while joining, the automatic join is skipped and says so. A device that is merely offline is far better than one stuck in a boot loop.

Multitasking

Tasks are green threads with real stacks, scheduled across both cores. A task can block anywhere — halfway down a call chain, inside a read, in the middle of a directory walk — which is what makes a background download and an interactive shell possible at the same time.

CommandDoes
psTasks, with state, core, CPU time and stack high-water mark
taskScheduled work
serviceLong-running background jobs
bgRun a command in the background
killAsk a task to stop
startupWhat runs at boot
watchRe-run a command on an interval
stressLoad generator, for checking the scheduler
A task is stopped at its next yield point, where it is by definition not holding a lock or half-way through a flash write. A task that never yields at all is force-terminated by the watchdog instead, and only after it has been asked politely first.

Automation & Scripting

.rps scripts run with script. The language matches v1's: the same statements, the same conditions, the same rule that two operands which both look numeric are compared as numbers.

set name = world
if $name == world
  echo hello $name
end

run and exec run a compiled .app. There is no interpreter on the device, so neither runs source.

Networking

Up to four networks are saved. Their passwords are stored in the clear, exactly as v1 stored them, because the board has no secure element to seal them with — anyone holding the flash can read them either way.

Web Tools

curl and wget speak HTTP and HTTPS. TLS is real: certificates are verified against a root bundle at /os/ca.pem, and an unverifiable connection is refused rather than downgraded.

curl https://example.com
wget https://example.com/file.bin

Downloads stream to flash as they arrive and show a live progress bar. Nothing is held whole in memory, so a file far larger than RAM downloads without trouble.

Package Manager

Packages are compiled .app binaries, loaded and relocated at runtime. A package registers shell commands, which then behave exactly like built-ins.

CommandDoes
pkg updateFetch the package list
pkg availableWhat can be installed
pkg install <name>Download, verify and install
pkg remove <name>Uninstall
pkg listWhat is installed
pkgdisable pkgenableTurn a package off without removing it
apps unloadLoaded apps; unload one
stockThe packages installed on first boot

Every download is checked against the SHA-256 in the index before it is installed. The official repository is configured out of the box, so pkg update works with no setup.

OS Updates

The device updates itself over the air.

update check
update install

The new image is downloaded to a staging area in flash and checksummed there. Only once it has been verified whole is the running image replaced, and the write itself runs entirely from RAM — an update that is interrupted leaves the staged copy untouched rather than a half-written OS.

User Management

CommandDoes
usersList accounts
mkacct rmuser usermodCreate, remove, modify
passwdChange a password
whoamiWho you are. Alias: id
sudoRaise privilege for one command
logoutEnd the session

Passwords are salted SHA-256. There are two privilege levels rather than v1's matrix: anything that changes the machine for everyone is admin-only, and sudo raises it for a single command, and only for someone who is already an admin.

Registry

reg reads and writes the persistent settings store; regreset puts a key back to its default.

reg get WiFi.Auto
reg set WiFi.Auto true

Diagnostics

CommandDoes
diagA health sweep across storage, memory, network and tasks
compatWhat this board supports and what it does not
logdumpThe log ring
inputstatWhat the terminal is actually sending, key by key
benchRPCMark, if installed

A crash is recorded in a black box that survives the reset, so the next boot can say which task was running, what it was doing and how long it had been stuck. If a task overruns its stack the tripwire at the bottom of it fires and the OS names the task instead of corrupting its neighbour and blaming something unrelated later.

Writing Packages

A package is a small C++ program compiled against a stable ABI and linked into a relocatable .app. It calls back into the OS through a function table rather than linking against it directly, which is what lets one binary keep working across OS releases.

See Package Development for the toolchain, the ABI and a worked example.

The original Pico and Pico W are back on the current release. v1.0's multitasking runtime could not fit in 264 KB and those boards stayed on v0.9.1; without an interpreter to host, v2 fits with room to spare.

Moving from v1

Most of what you know carries over. The commands, the output, the colours, the boot banner and the shell grammar were all checked against v1 rather than reinvented. What is genuinely different:

  • Packages are compiled. Existing .py packages need rebuilding as .app. Running Python under v2 is wanted, but not promised.
  • exec does not run source. There is no interpreter, so it runs a compiled app and says so plainly when handed a .py.
  • Two permission levels, not a matrix.
  • rawrepl is bootloader. v1 dropped to the MicroPython REPL so a host tool could reflash; the equivalent here hands USB back to the boot ROM.
  • Installing is a .uf2, not a file copy. There is nothing underneath it to install first.

The full comparison covers why the rewrite happened.

Known Limitations

  • The package catalogue is small. v1's twenty packages have not been ported yet. That work is underway and is the main thing between v2 and parity.
  • No ESP32 port yet. The OS core is portable; the context switch, storage and network layers are not.
  • No SD card support. It needs a driver.
  • No runurl. curl and script both exist, so it is a small gap rather than a missing capability.
  • Packages are not isolated. A package runs with the same privileges as the OS. MPU-backed isolation is planned.
